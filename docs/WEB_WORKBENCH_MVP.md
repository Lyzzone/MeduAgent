# 四入口网页工作台

首页 `/` 让用户明确选择任务，再进入 `/agents/qa`、`/agents/resume`、`/agents/grading`、`/agents/interview`。这里的路由依据是用户选择，不使用尚未验证的意图分类器。

| 工作台 | 当前可操作流程 | API | 实现状态 |
| --- | --- | --- | --- |
| 课程资料问答 | 输入问题、检索公开教程、显示摘录与出处 | `POST /v1/qa/events` | LangGraph 本地问答图，默认摘录预览 |
| 简历审查 | 输入简历文本和岗位描述、检查技能词与项目/量化表达 | `POST /v1/resume/review` | 确定性规则基线；不生成或修改个人经历 |
| 试卷批改 | 输入题目、参考答案、作答与满分；客观题精确匹配，主观题等待教师复核 | `POST /v1/grading/check` | 确定性规则基线；不发布正式分数 |
| 模拟面试 | 选择方向、获取问题、提交回答并查看关键词覆盖与追问 | `POST /v1/interview/turn` | 固定题库和关键词提示；无会话持久化或能力评定 |

前端为静态 HTML/CSS/JavaScript，由 FastAPI 同源提供。首页卡片是明确任务路由；课程问答继续使用独立 `qa.html`，其余三个工作台共享组件与脚本，但各自调用不同的 API 和业务函数。结果卡片使用 `textContent` 渲染用户相关文字，避免把输入当 HTML 执行。页面保留返回首页链接、键盘焦点、窄屏布局和加载/错误提示。

**数据边界：**现阶段没有账号与权限隔离。简历和学员作答只在本次请求中处理，代码不持久化；若未来公开部署，需先补认证、输入保护、速率限制、日志脱敏和删除机制。两份私有 PDF 仍只能本地 CLI 查询，网页不开放其原文。公开问答使用已核验许可的教程语料。

**下一阶段：**简历应增加事实提取与逐项证据核查；主观题应引入 rubric、教师审核状态和幂等保存；面试应加入持久化轮次、追问策略与可复核反馈。三条业务再逐步接入 LangGraph 子图和模型适配，并使用独立标注集评测。当前四个按钮证明导航与业务分流可运行，不代表四个完整 Agent 已交付。

本地验证：`python -m pytest -q` 覆盖四条路径、QA 回归、三个规则 API、主观题审核边界。浏览器中用各页“填入示例”验证交互，面试页可先留空回答获取题目。
