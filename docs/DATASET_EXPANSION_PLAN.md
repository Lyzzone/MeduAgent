# 数据与评测扩充方案 v0.1

初版日期：2026-09-25。更新：2026-09-26。九篇公开教程和 20+8 条单人标注冻结题已落地，首轮结果见 [阶段 B 报告](STAGE_B_QA_EVAL.md)；下述 30–60 份资料与 200–300 题仍是后续目标。

## 当前基线能说明什么

原 M1 基线语料为 6 篇免费公开的中文 IT 文章，共约 158 KB、156 个检索片段；开发集是 12 个正例（每篇 2 个）和 3 个明显跨领域负例。问题由开发者依据文章章节编写，检索规则又根据该开发集失败案例调整。`12/12 Recall@5` 只说明这 12 题在当前版本被召回，不能推断新课程、真实学员问法或生产环境表现。三个负例也不足以测出课程内无答案问题的误答风险。

更重要的是，当前指标只测**检索片段**，默认页面是原文预览。尚无真实模型生成答案的正确性、证据支持性、引用准确性、费用、并发、权限或另外三条业务路径评测。

## 扩充原则

优先增加**有代表性的差异**，其次才增加数量。新增资料须有清晰再分发许可或用户授权；记录来源、版本、许可证、作者和校验值。公开仓库只放允许公开的语料与合成样例，真实学员简历和答卷不得直接使用。对旧教程标记年份和技术版本，避免将过时示例作为现行生产建议。

以下数字是本项目下一轮的**工作目标，不是通用生产标准**：

| 阶段 | 资料 | 标注问题 | 用途 |
| --- | --- | --- | --- |
| 原开发样本 | 6 篇、156 片段 | 12 正例 + 3 负例 | 冒烟与回归；已反复用于调参 |
| 下一轮作品集基线 | 约 30–60 份获授权/开放许可资料，覆盖至少 5 类 IT 主题与 Markdown、PDF 等常见格式 | 约 200–300 条人工核对样例，正例、课程内无答案、跨领域、歧义与对抗输入分层 | 检验解析、引用、不同主题和问法；冻结其中一部分作独立验收 |
| 真实试运行 | 使用实际获授权课程目录与内容，按资料版本管理 | 经同意且脱敏的真实问题持续补入；每个关键用户群/任务类型单独统计 | 结合线上失败、人工反馈、延迟和费用监控，不用固定公开数据量代替场景验证 |

资料数与题数可按标注人力调整；不能为了达到数量而复制近似文章或自动生成大量未审核的简单题。30–60 份资料也只足以支撑受控作品展示，并不自动等于生产规模。

## 问答数据覆盖矩阵

每条样例至少记录：`question`、场景/难度、资料版本、预期是否可答、所有可接受的证据片段 ID、参考答案要点、拒答原因、标注者与复核状态。

| 分层 | 必须包含的案例 |
| --- | --- |
| 表达变化 | 原词、同义改写、口语、错别字、中英混写、缩写、代码/命令提问 |
| 推理范围 | 单段直接回答、跨段综合、两篇比较、版本冲突、问题缺少必要条件 |
| 无答案 | 完全跨领域、课程内但文档未覆盖、旧版本资料无法回答最新版本、问题本身含错误前提 |
| 检索干扰 | 多篇都含相同关键词、相似标题、重复/过期文档、长代码块与表格 |
| 风险与权限 | 文档内提示注入、越权提问、敏感内容、恶意上传；在实现相应能力后再测试 |

只用章节标题生成的问题会高估关键词检索效果。新问题应先按学员真实任务独立编写，再标注证据；至少复核一部分易争议和多证据样例。每题允许多个相关片段，避免把另一个正确片段错误判为漏检。

## 四条业务路径分别建数据

- **课程问答**：资料、问题、证据片段、答案要点、拒答理由。
- **简历诊断**：自制或授权脱敏简历、岗位描述、事实清单与改写边界；测事实虚构和建议可操作性。
- **试卷批改**：自制题目、标准答案、分项 rubric、不同质量作答及教师判分；主观题只评模型建议与教师一致性。
- **模拟面试**：岗位与难度、题目、模拟回答、追问机会、rubric；评价反馈是否基于实际回答，不做真实录用判断。

四条路径不能共用一个总“准确率”；各自有不同的真值、权限和失败成本。

## 划分、指标与发布规则

1. 先固定语料快照、切分版本、模型/索引版本和标注说明，再划分开发集与**不参与调参**的冻结测试集。近义改写和同模板问题要按组划分，减少泄漏；独立新增文档可另设迁移压力集。
2. 检索比较保持相同语料、相关片段标注、问题、top-k 和权限范围；分别报告 FTS5、dense、混合、重排的 Recall@5、逐题结果、延迟与费用。BM25/FTS5 是当前实际基线。
3. 生成答案还需人工核查答案要点、逐句证据支持、正确拒答和引用可定位。LLM 评委可辅助筛查，但抽样人工复核分歧。
4. 报告分层样本数、成功/失败原始计数、典型失败案例。任何在冻结测试集上发现问题后进行的修改，只在下一版独立集验收时声称改进。
5. 真实试运行后再利用经同意且脱敏的失败问法补充回归集，并监测线上错误、p95 延迟与费用。脱敏数据不自动获得公开发布许可。

参考：[LangSmith 官方评测类型](https://docs.langchain.com/langsmith/evaluation-types)区分上线前 curated offline evaluation 与上线后的在线监控/反馈；[Ragas 官方指标列表](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/)将检索覆盖、回答相关性和忠实度分开；[BEIR 论文](https://arxiv.org/abs/2104.08663)强调跨任务/领域检索表现差异。因此本项目不会用一个小型同质题集的高分替代真实场景验证。
