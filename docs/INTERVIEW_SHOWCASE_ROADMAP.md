# MEduAgent 面试展示版改造路线

更新：2026-09-26。本文是实施计划；功能完成状态以 README 和实际测试证据为准。

## 完成定义

面试官从 GitHub 克隆后，不用真实密钥或私有 PDF 就能启动公开演示数据，走通四条路径。测试和评测可复现；线上 agent.cuitopendoor.top 的版本与 Git tag 对齐，HTTPS 可用。README 写清架构、5 分钟演示路径、失败案例和指标原始分子/分母。私有 PDF、学习笔记、密钥和真实求职者/学员数据不进入仓库。

展示主线是：明确任务路由 → 专属工作流 → 证据与结构化结果 → 人工确认或拒答 → 评测与部署。四个网页入口本身不等于四个完整 Agent。

2. 冻结独立问答集，覆盖事实定位、对比、同义改写、无答案、过时知识和引用错误；固定文档版本、相关片段、top-k 和评测代码后再测。

## 阶段 C：让另外三条业务形成可演示闭环

- 简历：用虚构简历作输入，输出事实片段/位置 → 岗位要求 → 缺口 → 建议草稿。模型只能基于已提取事实建议写法；用户确认后才采用，不自动编造指标或经历。
- 批改：客观题保留规则基线；主观题引入 rubric 项、依据片段和建议分，使用 LangGraph interrupt 暂停等待教师修改/确认；正式结果保存前校验审核身份与版本。官方依据：https://docs.langchain.com/oss/python/langgraph/interrupts
- 面试：用任务 ID 保存岗位、难度、轮次与回答，支持追问、查看和删除；反馈引用回答中的具体内容，避免用关键词命中冒充能力评分。
- 统一编排：保留用户显式选择作为路由主依据；建立共同的 task_type/status/evidence/review_status 契约，再把业务工作流接入主图。checkpointer 保存线程状态和中断恢复，长期业务数据另存 SQLite；简历原文或学员答案全文不放检查点。依据：https://docs.langchain.com/oss/python/langgraph/persistence

验收：各流程有成功、拒绝/需补充、错误路径；批改暂停后重启服务仍可恢复且不会重复发布；简历建议可回溯原文；面试多轮状态可重放并可删除。
